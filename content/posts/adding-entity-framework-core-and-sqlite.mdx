In the [introduction to Minimal APIs](https://sudi77.hashnode.dev/getting-started-with-aspnet-core-7-minimal-apis), our endpoint returned a hardcoded list. Now let's add a data source to store and retrieve recipes. We'll use SQLite as the database and Entity Framework Core to talk to it.

First, add the packages for SQLite and EF Core. In your terminal, go to the root directory of your project and run:

`dotnet add package Microsoft.EntityFrameworkCore.Sqlite`

`dotnet add package Microsoft.EntityFrameworkCore.Design`

The first package is the SQLite provider for EF Core. The second contains the design-time tools that the `dotnet ef` commands use to create migrations.

Next, add the recipe model. Create a folder named `Models` in your project directory, add a class file called `Recipe.cs` inside it, and define the model:

```csharp
namespace CookingAPI;

public class Recipe
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Description { get; set; }
}
```

The `Recipe` class describes the data our API stores. With the model in place, we can configure EF Core.

The next step is the DbContext. It represents a session with the database and connects our application code to it. To learn more, read the [DbContext documentation](https://learn.microsoft.com/en-us/dotnet/api/system.data.entity.dbcontext?view=entity-framework-6.2.0).

Add a folder called `Data` to the project and create a class file called `AppDbContext.cs` inside it. You can choose another name, but many .NET developers call it AppDbContext by convention. Define the database context:

```csharp
using Microsoft.EntityFrameworkCore;

namespace CookingAPI.Data;

public class AppDbContext: DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options): base(options)
    {  
    }
    public DbSet<Recipe> Recipes { get; set; }
}
```

Now connect the API to the SQLite database. Open `Program.cs` and add the following code just below the `builder` variable:

```csharp
using CookingAPI.Data;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddDbContext<AppDbContext>(options =>
{
    options.UseSqlite(builder.Configuration.GetConnectionString("DefaultConnection"));
});

var app = builder.Build();

app.Run();
```

This registers EF Core and points it at a connection string called `DefaultConnection`. We also imported the `Microsoft.EntityFrameworkCore` namespace, which contains the `UseSqlite` method.

EF Core looks for `DefaultConnection` in `appsettings.json`, and it isn't there yet. Open `appsettings.json`, which was created with the project, and add a section for the connection string:

```csharp
    {
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=./Data/app.db"
  }
}
```

The new `ConnectionStrings` section sits below `"AllowedHosts": "*"`. Its `DefaultConnection` value points to `app.db`, the SQLite file that holds our data, in the project's `Data` folder.

Next, create a migration for the `Recipe` model. Migrations let EF Core manage changes to the database schema. Run:

`dotnet ef migrations add InitialCreate`

This creates a migration that adds a `Recipes` table matching the `Recipe` model. To apply it and create the database, run:

`dotnet ef database update`

Now we can seed the database with some initial data. Update `AppDbContext` to seed the `Recipes` table with a few recipes:

```csharp
using Microsoft.EntityFrameworkCore;

namespace CookingAPI.Data;

public class AppDbContext: DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options): base(options)
    {  
    }
    public DbSet<Recipe> Recipes { get; set; }
}

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Recipe>().HasData(
        new Recipe { Id = 1, Name = "Somba wali", Description = "Sweet and common meal eaten in the Central Africa." },
        new Recipe { Id = 2, Name = "Wali Maharagwe", Description = "Rice and beans mostly in the Central African cuisine" }
    );
}
```

Finally, let's add endpoints for creating, retrieving, updating, and deleting recipes. Here is a basic version:

```csharp
using CookingAPI.Data;
using CookingAPI.Models;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddDbContext<AppDbContext>(options =>
{
    options.UseSqlite(builder.Configuration.GetConnectionString("DefaultConnection"));
});

var app = builder.Build();

app.MapGet("/", async (AppDbContext db) => await db.Recipes.ToListAsync());

app.MapGet("/recipes/{id}", async (AppDbContext db, int id) =>
{
    var recipe = await db.Recipes.FindAsync(id);
    if (recipe is null)
        return Results.NotFound($"Recipe with ID {id} not found");
    return Results.Ok(recipe);
});

app.MapPost("/recipes", async (AppDbContext db, Recipe recipe) => {
    await db.Recipes.AddAsync(recipe);
    await db.SaveChangesAsync();
    return Results.Created($"/recipes/{recipe.Id}", recipe);
});

app.MapPut("/recipes/{id}", async (AppDbContext db, int id, Recipe recipe) => {
    var existingRecipe = await db.Recipes.FindAsync(id);

    if (existingRecipe == null) 
        return Results.NotFound($"Recipe with ID {id} not found");
    existingRecipe.Name = recipe.Name;
    existingRecipe.Description = recipe.Description;

    await db.SaveChangesAsync();

   return Results.Ok(new { message = "Recipe successfully Updated" });
});

app.MapDelete("/recipes/{id}", async (AppDbContext db, int id) => {
    var recipe = await db.Recipes.FindAsync(id);
    if (recipe == null) return Results.NotFound($"Recipe with ID {id} not found");
    db.Recipes.Remove(recipe);
    await db.SaveChangesAsync();
    return Results.Ok(new { message = "Recipe successfully deleted" });
});

app.Run();
```

These endpoints use dependency injection (DI), which is built into .NET. With DI, an object receives the objects it depends on instead of creating them itself, which keeps the code modular and easier to test.

Each endpoint takes `AppDbContext db` as a parameter. When a request comes in, .NET creates an `AppDbContext` instance and passes it to the endpoint, which uses it to read, add, update, or delete recipes in the SQLite database.

## Conclusion

In this post, we connected a Minimal API to SQLite with EF Core. We defined a model and a DbContext, configured the database, created and tested API endpoints, and saw how dependency injection gives each endpoint its DbContext.
